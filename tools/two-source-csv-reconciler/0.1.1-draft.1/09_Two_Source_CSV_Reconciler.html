Two-Source CSV Reconciler

Catch missing records, duplicate keys and changed fields before anybody calls a data migration complete.

WORK IN PROGRESS: sanitized source handoff. This is an unfinished browser-only prototype, not a production service. Use fictional inputs. See README.md for evidence, limitations, contribution scope and the scoped MIT license.

1. Compare two fictional data snapshots

Synthetic-only prototype. Do not import real personal, customer or employer files. All calculations occur in the browser without network access, cookies or storage. Imported CSV, file names, record IDs and exported exception details can still contain sensitive data. For this pilot use fictitious identifiers and no tax, bank, site, security, credential or customer information. A matching report is not proof that original data was accurate, complete or authorized for use.

Limit: 300 KiB / CSV, 1,000 records per side, 40 columns, 2,000 characters per cell, 12 mapped field pairs. Matching is one-to-one by unique nonblank key. Ambiguous duplicate keys are never silently paired. Original cell values are preserved only in private exception CSV/TXT exports. Empty cells are legitimate values, but a blank key is not.

3. Safe next steps

1. Verify that both snapshots came from the intended, legitimate systems and dates. 2. Check ownership, privacy and permission to process the records outside their original system. 3. Resolve duplicate keys before trusting row-level comparisons. Review missing and extra records with the source owner. 4. Investigate different values with original evidence, then rerun with a fresh authorized snapshot. 5. Obtain human acceptance before changing master data, contacting a customer, exporting externally or publishing an example. PD-RECON-1: The AI handoff contains aggregate counts ONLY and never authorizes changes.
