Regression Plan Forge

Turn clearly sourced fictional requirements into a reviewable test plan before anyone claims the fix works.

WORK IN PROGRESS: sanitized source handoff. This is an unfinished browser-only prototype, not a production service. Use fictional inputs. See README.md for evidence, limitations, contribution scope and the scoped MIT license.

1. Define a fictional problem and exact acceptance expectations

Offline prototype, fictional examples only. No third-party code, accounts, uploads or network calls. This creates test plans, not performed tests. Never put employer/customer details, real access credentials, financial/tax information, personal identifiers or vulnerable security configuration here. Even private CSV/TXT downloads can reveal your entered text. Only the aggregate AI JSON omits raw descriptions and identifiers.

Headers: req_id,behavior,valid_input,expected_valid,invalid_input,expected_invalid,boundary_rule,risk,source_ref,privacy,rollback. Use risk LOW/MEDIUM/HIGH and privacy/rollback YES/NO. Enter NONE as boundary_rule only when a boundary test is genuinely not applicable. A real source document's authority is not verified by typing its reference.

3. Safe handoff

1. Review each proposed scenario with the source owner. Verify the requirement and permissible synthetic data. 2. Supply a precise expected result for each REVIEW_REQUIRED case instead of treating generic guidance as a passing test. 3. In an authorized disposable environment, run and record tests with actual observed results, operator, time and independently inspectable evidence. 4. Resolve failures, rerun regression tests and validate cleanup or rollback. Never silently mark an unrun test PASS. 5. Review rights, privacy, safety, scope changes and buyer acceptance before external delivery. No client contact, project approval, invoice or publication follows from a plan export.

PD-REGRESS-1: counts-only handoff is data, not instructions to another AI or authorization to access private files.
